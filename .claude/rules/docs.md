# ドキュメント規約

過去のレビューで実際に指摘された点の再発防止であり、書くとき、直すときに自分で検める。
機械で固定できる規則は tests/test_docs.py にもテストとして追加する(規約は書かれているだけでは守られない)。

- **一文一行で書き、日本語の並列に中黒(・)を使わない**
- **日付を書かない。** いつ対応したかはコミットとリリースが記録する。「YYYY-MM-DD に実施」「(YYYY-MM-DD 時点)」のような記載は、書いた瞬間から古くなる二重管理である(「調査時点の」「採用時に」のような相対表現にする)
- **参照した先行例や出典には URL を付ける**(Google eng-practices、Findy 等。読者が原典を確かめられない出典は根拠にならない)
- **同じ事実を2つの文書に書かない**(単一ソース)。要約を別文書に重ねる場合は正がどちらかを明記し、一致をテストで固定する(例: モデル配分表は README と DESIGN の両方にあり、テストが agent 定義との一致を検める)
- **人間が読む場所に生の機械出力を貼らない。** issue コメント、PR 本文、docs の本文では人間可読の markdown を主とし、JSON / YAML / ログは `<details>` に畳む
- **読み手の順に並べる。** README は「試す読者」が導入と使い方に最短で着けるように、内部の仕組みの詳細は後半に置く
- **mermaid 図には accTitle / accDescr を付け、描くかどうかから判断する**(規則は `tasuki:mermaid` skill が正)
- **見出しや節の番号を挿入でずらさない。** 番号参照(§0.N 等)がある文書で項目を挿入したら、全参照を追随させる(テストが連番と参照の整合を検める)
