# mermaid

図はテンプレートを埋めて作るものではない。
何を見せたいかを決め、それに図が要るかを判断し、要るなら図種を選ぶ。

## 1. 図にするかを決める

図は表より高価である。
縦幅を奪い、差分が読みにくく、構文を誤ると図全体がエラー表示になる。
次をすべて満たさないなら、表か箇条書きにする。

- 見せたいのが**構造**(分岐、合流、循環、階層)であり、並びや値ではない
- その構造が2要素1関係より複雑である
- 図に載る情報が、隣に置く表の再掲になっていない

判断の目安として、**図が固有に持つ情報は辺だけ**である。
ノードのラベルが表の行をなぞっているなら、その図は表の再掲に辺を1本足しただけになる。
ノード2個で辺1本の図は、本文に `A → B` と書けば足りる。

## 2. 図種を決める

| 見せたいもの | 図種 |
|---|---|
| 依存や工程の構造、分岐と合流 | `flowchart` |
| 1つの対象が辿る状態と、戻る経路 | `stateDiagram-v2` |
| 登場人物の間の時系列のやり取り | `sequenceDiagram` |
| データの実体と関係 | `erDiagram` |

選ばない判断も持っておく。

- `gantt`:各項目に日付か期間が必須のため、時間軸を持たない計画には使えない
- `mindmap`:単一ルートの木であり、合流(fan-in)を表せない
- `kanban` や `requirementDiagram` のような新しい図種:mermaid 本体(11.16 で確認)は描画するが、GitHub が使う mermaid のバージョンは別に管理されている

新しい図種を採用する前に、対象リポジトリの issue コメントで1件試して描画を確かめる。

## 3. GitHub 上での制約

- `click` とノード内リンクは無効化されるため、**リンクは図の外の表に置く**
- テキスト量と辺の数に上限があるため、大きい図は完了部分を1ノードに畳むか分割して貼る
- 構文エラーでは部分描画されず図全体がエラーになるので、貼る前に構文を確かめる

## 4. 壊さないための記法

- ノードのラベルはダブルクォートで囲む(`#`、`/`、`()`、`<br/>` を含むため)
- 改行は `<br/>`、強調は `<b>...</b>` を使う(`\n` は改行にならない)
- `end` をノード ID にしない(subgraph を閉じる予約語)
- `requirementDiagram` の `text:` に日本語を書くときは引用符で囲む(囲まないと lexical error になる)

## 5. 凡例をグラフの中に作らない

凡例を `subgraph` として図の中に置くと、レイアウトエンジンが凡例のノードを本体と同格に扱う。
結果として凡例が図の上部を占め、本体より先に目に入る。
実測では、ノード2個の計画図で凡例が描画面積の50%と高さの69%を占めた。

凡例は図の外に markdown の1行として書き、**実際に出現した状態だけ**を載せる。
使われていない状態を凡例に残すと、その状態が存在するかのように読める。

## 6. 色は意味にだけ使う

`classDef` で状態ごとに定義し、`:::` で当てる。

```
classDef done fill:#2da44e,stroke:#1a7f37,color:#fff
A["#40 スキーマ"]:::done --> B["#41 API"]
```

装飾のための色を足さない。
色で表した情報をラベルにも書いているなら、どちらかが冗長である。
