# 計画コメント

親 issue に1件だけ置き、進行に応じて同じコメントを編集して更新する。

## 答えるべき問い

読み手は issue を見に来た人間である。
次の3つに答えられていれば、その計画コメントは役目を果たしている。

1. いま人間がすべきことは何か(マージ待ちの PR、裁定待ちの triage)
2. どこで止まっていて、それが何を堰き止めているか
3. 親要件の取りこぼしはないか

答えを本文の先頭に置く。
図はこの答えを補強するときだけ足す。

## 構成

必須は次の2つだけである。

- 冒頭の要約:上の3つの問いへの答えを1〜2行で書く
- 一覧表:子ごとに issue リンク、対応する親要件、状態、PR、予算

図は下の条件を満たすときだけ足す。

## 図を描く条件

依存の図は、**表では表せない構造があるときだけ**描く。
次のいずれかを満たすことを確認してから描く。

- 合流または分岐がある(入次数または出次数が2以上の子がある)
- レイヤーが3段以上ある
- 子が5件以上ある

満たさないなら描かない。
一直線の依存は本文に `#31 → #32` と書けば足りる。
2ノード1エッジの図は、表の再掲でしかなく、紙面だけを奪う。

要件カバレッジの図も同じ判断による。
親要件と子が1対1で対応しているなら描かない(それは表の1列である)。
1つの親要件を複数の子で分担する、1つの子が複数の親要件をまたぐ、対応する子が無い親要件がある、のいずれかがあるときに描く。
孤児の親要件があるなら、それを図の主役にする。

## 図に何を載せるか

- 載せる:issue 番号、短いタイトル、状態(色)、依存の辺
- 載せない:一覧表に既にある情報(PR 番号、予算、詳細なゲート名)

図と表で同じ情報を二度書かない。
図は構造を、表は詳細を受け持つ。
ノードのラベルが表の行をなぞっているなら、その図に固有の情報は辺だけである。

## 状態の決め方

ラベルと PR の状態から決める。

| 状態 | 判定 |
|---|---|
| 完了 | PR が ready |
| 進行中 | `loop:in-progress`、または `gate:g2-passed` 以降で未 ready |
| 差し戻し | `gate:*-returned` |
| 裁定待ち | `loop:triage` |
| 未着手 | 依存待ち、または未処理 |

凡例は、**実際に出現した状態だけ**を本文の1行として書く。
図の中に凡例のノードを作らない(レイアウトエンジンが凡例を本体と同格のノードとして配置し、図の主役を奪うため)。

## 更新

同じコメントを編集して更新する。
新しい計画コメントを増やさない。
子の集合が変わった場合は、最新の計画コメントを正とする。

図の記法と図種の選び方は `tasuki:mermaid` skill を参照する。
